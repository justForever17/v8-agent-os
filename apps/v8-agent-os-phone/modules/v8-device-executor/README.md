# Android device executor

This tracked local Expo module is compiled into the Phone APK. It has no model, script runner, chat-token access, foreground-service impersonation, or boot receiver. Module registration and chat profile changes do not connect or arm it. A local user enables system accessibility and notifications, chooses exact application packages, enrolls against an explicit HTTPS Engine origin, and starts a control session. The notification and anonymous-accessible `/device-executor` screen stop locally before waiting for any network operation.

The native controller owns its independent Keystore-encrypted credential, origin/authority binding, control session and bounded SQLite receipts. The Engine's existing device/lease/grant/episode owner supplies authorization. Logout of the exact bound Phone authority first stops this module and attempts device revocation; other chat profiles do not affect it. Failed revocation persists and prevents local rearming until retried. The same APK shares a UID and process; this is not OS sandbox isolation.

Fixed capabilities are `android.observe` (bounded accessible node tree), `android.capture` (single JPEG frame), and `android.action` (node click/long-click/text/scroll, plus frame-based `tap`/`swipe`). Node actions use the real node-map revision; coordinate actions use a real captured frame, geometry revision, rotation and viewport and never require a fabricated node map. Password nodes, the host APK, Android permission controllers, settings and lock screens are excluded. There is no continuous MediaProjection session. Truncated trees/text carry `partial: true`.

Android 14+ captures the exact allowed window using `takeScreenshotOfWindow`. Before coordinate dispatch, another window screenshot checks secure-content refusal without encoding or uploading the probe. The current app/window/rotation/layers/geometry are checked before capture, on callbacks, before each upload stage and before gesture dispatch. Coordinates are pixels of the uploaded frame and map into its recorded window viewport; system-bar regions, overlays, magnification and touch exploration prevent coordinate dispatch. `dispatchGesture=true` only means dispatch; `onCompleted` reports driver completion with business verification still pending. `onCancelled` is an unknown outcome. A later explicit `android.capture` can supply new pixels; the immediate post-action observation uses nodes only when separately granted.

Android 11–13 has no window capture API or public secure-window probe. A separate local **whole-display capture** switch is off by default; both the target app grant and `android.capture/display` grant are required. The scope may include other apps and system chrome and is not advertised as per-app isolation. Android's secure-content screenshot protection remains in force, but these versions may render protected areas black instead of returning a secure-window error. Such whole-display frames can never authorize coordinate actions. The UI reports coordinate actions unavailable below Android 14. Existing node actions continue to use their own observation contract.

JPEG encoding is native, bounded to an sRGB frame with longest edge 1600, quality 80, and 2 MiB, with input allocation capped at 8 Mi pixels. Pixels never cross the React Native bridge, WSS control frames, or local files. Native reserves an exact media handle through `/api/executor/media`, sends raw JPEG bytes to the same authority's exact PUT path, then includes only `mediaId` and frame metadata in the receipt. Engine publishes its owned artifact after validating the receipt. Stop/revocation/session changes cancel native work and HTTP calls and discard unpublished handles; late callbacks cannot start uploads, gestures or publish receipts. Network cancellation cannot retract bytes already sent, and an already-dispatched Android gesture has no public immediate cancel API; those outcomes remain unknown until reconciled. Unpublished server media expires even when cleanup cannot reach the server.

`received` and `started` are persisted before driver invocation. Driver completion is `succeeded` with `businessVerification: unverified`; post-observation is evidence for Engine acceptance, never an automatic verified claim. A started action interrupted by disconnect/stop/restart becomes `unknown_outcome`. Duplicate command IDs return stored receipts after digest checks, with no re-execution. New commands require current authority/device/boot/local session/lease epoch/grant revision, local application scope, server grants, original TTL and deadline. Receipt storage is capped at 512 records; settled outcomes expire after seven days, while unsettled and unknown outcomes remain for reconciliation. Exhaustion fails closed. Old commands outside retention still fail the maximum 30-second action TTL. Storage failure also closes local admission and the connection; it cannot prevent Stop or turn an uncertain effect into success.

The system service invalidates snapshots on accessibility events, stops on observed local interactions and screen-off/lock, and checks the live window and node again before applying. Android does not expose every ordinary raw touch to a normal accessibility service without changing touch exploration behavior. This module does not consume touchscreen events or claim universal human-touch interception; unseen input is additionally fenced by fresh snapshot/window/node validation and the always-visible local Stop action. OEM service reclaim can disconnect it; reopening locally is required after process death. No claim of unrestricted background availability is made.

## Build and verification

Window screenshots on API 34 exclude accessibility-overlay pixels by Android's
window capture contract. Native retains the real display obstruction rectangles:
a tap inside one, or a swipe whose bounding rectangle crosses one, is rejected
with `coordinate_in_obstructed_region`. A fresh frame is required after window,
overlay or orientation changes. Display capture keeps its stricter scope checks.
Interaction bounds combine platform bar/cutout/gesture insets and actual
accessibility-window blockers; no OEM-specific navigation-bar size is assumed.

Android Skia may attach an ICC APP2 segment even to an explicitly sRGB bitmap.
Native removes APP1–APP15 and comment metadata after encoding, preserves the
entropy-coded image bytes, and hashes the actual metadata-free upload. Server
validation remains strict and needs no image decoder.

From the Phone directory, use its locked Expo 55 dependencies and `npx expo prebuild --platform android --no-install`. The local module is discovered through `expo-module.config.json`; Gradle merges the tracked module manifest/resources. Run `android/gradlew :v8-device-executor:testDebugUnitTest :app:assembleRelease` with the installed JDK/SDK. Test Android API 30 and newer, current Android behavior and an OEM device separately; an APK build alone does not validate accessibility permissions or action effects.

The synthetic target under `tests/android-executor-fixture` has no network/account/data permissions. Build with `android/gradlew -p tests/android-executor-fixture :app:assembleDebug`. It contains an increment button, a no-op button, editable synthetic text and a scene-change control. The no-op deliberately distinguishes driver acceptance from business completion. Its additional canvas-only scene draws tap/swipe counters without a virtual node map; the exact fixture-only `canvas`, `secure_on` and `secure_off` intents prepare future screenshot/secure-window tests without touching another app.

Native instrumentation uses a separate test APK (`expo.modules.v8executor.test`) and never reads the existing Phone account. Start the Engine's isolated `tests/scripts/run_device_executor_live.py`, then run `scripts/prepare-executor-native-tests.ps1 -PublicTestCa <public-ca.pem>` and build `:v8-device-executor:assembleDebugAndroidTest`. The copied public certificate is ignored and trusted only by the test source set for `localhost`; release never trusts it. Forward `adb reverse tcp:9533 tcp:9533`, install the two test APKs, and manually grant the test service and notification from `ExecutorTestActivity`. Do not change system authorization with adb settings commands.

`ExecutorNativeTest` checks strict wire parsing, real SQLite crash recovery and authority-scoped receipt lookup. Real service testing uses the separate `ExecutorTestActivity` and an external `--live` harness, because Android instrumentation restarts the package and disrupts an already bound accessibility service. Start the test activity with the fixed `fixtureCommand=connect` intent after manually granting the test service. Its target is always the synthetic fixture, and its HTTPS origin is always the isolated localhost Engine. The fixture ticket is fetched and consumed inside native code. No credential or ticket belongs in shell arguments, reports or test fixtures. Production Phone upgrade requires a matching signing certificate; never uninstall a user's installed Phone to bypass a signature mismatch.

For screenshot/gesture changes, run the pure `FramePolicyTest` in addition to `CommandGuardTest`, and compile `ExecutorMediaTest` with the instrumentation APK. The media test intercepts actual OkHttp bodies and main-thread callbacks with synthetic bytes; it does not capture a real screen or prove an OEM's screenshot/gesture implementation. Real-device follow-up must separately verify window-only pixels versus overlays, protected windows, API 30–33 full-display opt-in, screenshot-only tap/swipe, rotated/resized viewport mapping, cancellation during capture/upload/gesture, and no post-Stop publication. Check generated JPEGs against the Engine media validator. These platform cases are not satisfied by a successful build or pure JVM tests.

API references checked for this implementation: [AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService), [ScreenshotResult and uptime timestamps](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService.ScreenshotResult), [AccessibilityWindowInfo](https://developer.android.com/reference/android/view/accessibility/AccessibilityWindowInfo). Android SDK 36 headers are the compile-time source; minSdk remains 30.

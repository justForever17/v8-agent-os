# 定时任务配置指南

定时任务 (Cron Jobs) 允许 V8Chat 后台引擎根据设定的时间周期，自动、静默地执行各类自动化任务。无论是定期的数据备份、记忆提炼，还是日常的消息推送，都可以通过该面板进行管理。

---

## 🕒 Cron 表达式基础

所有的任务都依赖标准 Cron 表达式来确定执行周期。一个 Cron 表达式由 5 个部分组成，顺序为：**`分 时 日 月 周`**。

| 位置 | 含义 | 允许值 | 特殊字符示例 |
| :--- | :--- | :--- | :--- |
| 第 1 位 | 分钟 (Minute) | `0-59` | `*` (每天的每分钟), `0,30` (整点和半点) |
| 第 2 位 | 小时 (Hour) | `0-23` | `*` (每天每小时), `8-10` (8、9、10点) |
| 第 3 位 | 日期 (Day of month) | `1-31` | `*` (每天), `*/2` (每隔一天) |
| 第 4 位 | 月份 (Month) | `1-12` | `*` (每月) |
| 第 5 位 | 星期 (Day of week) | `0-7` (0和7均代表周日) | `1-5` (工作日周一至周五) |

> 💡 **快捷提示**：如果你不熟悉格式，可以在配置表单中使用下拉框的**预设时间**。选择“每天特定时间”可以直接在输入框中填入 `HH:mm` (如 `08:30`)，系统会自动转换为 `30 08 * * *`。

## ⚡ 执行类型 (Action Types)

V8Chat 的后台核心调度器 (`ActionExecutor`) 支持三种基本类型（和 Hooks 类似），可以满足几乎所有类型的计算和执行需求。

### 1. 命令行脚本 (Command)
使用 `subprocess` 触发操作系统级脚本或可执行文件。
- **目标示例**：`bash upgrade.sh` / `node dist/index.js`
- **使用场景**：清理临时目录文件、执行系统维护或者跑某个第三方的 Node/Go 程序。

### 2. Python 脚本 (Python)
以安全抽象语法树 (`AST`) 将指定的 Python 源文件加载并在当前 Engine 虚拟环境中执行。
- **目标示例**：`scripts/cron_nightly_memory_batch.py`
- **使用场景**：比如每天凌晨将当天的分散对话数据提炼、汇总为周期的长期记忆总结。这正是 V8Chat 保障记忆系统不爆炸的基石系统。脚本会被抛入后台协程执行，避免阻塞。

### 3. Agent 工作流 (Agent)
直接调用 LangGraph 并传入特定的预置 Prompt 让 Supervisor 或其他自定义专属 Agent 于后台唤醒并打工。
- **目标示例**：`research_agent` / `supervisor`
- **参数 (Payload) 示例**：
  ```json
  {
    "task": "去搜索获取最新的 HackerNews Top 10，然后写入今日资讯摘要",
    "notify_user": true
  }
  ```
- **使用场景**：让 AI 机器人团队每天早晨为你主动准备早报，打破“问一声答一句”的呆板交互瓶颈，使其做到“主观自动化”。

## 📊 全局执行日志

每次配置的定时任务执行完毕后，系统都会在底层的 SQLite `knowledge.db` 中忠实记录一条包含任务状态、执行耗时与异常日志的数据（`execution_logs` 表）。

只要点击顶侧边栏的 **"执行日志"** 切换到日志视图，就可以监控历史情况。即使夜间的离线抓取任务意外中止，你也可以第一时间从报错栏发现问题。

> ⚠️ **并发注意事项**：如果在日志中发现大量处于 `running` 或耗时极长的数据行，那意味着前面的任务因为请求超时等原因尚未结束，系统却又发起了下一次调度。此时应当适当调大 Cron 触发间隔。

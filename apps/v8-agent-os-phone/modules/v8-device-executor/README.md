# Android device executor

This tracked local Expo module is compiled into the Phone APK. It has no model, script runner, chat-token access, foreground-service impersonation, or boot receiver. Module registration and chat profile changes do not connect or arm it. A local user enables system accessibility and notifications, chooses exact application packages, enrolls against an explicit HTTPS Engine origin, and starts a control session. The notification and anonymous-accessible `/device-executor` screen stop locally before waiting for any network operation.

The native controller owns its independent Keystore-encrypted credential, origin/authority binding, control session and bounded SQLite receipts. The Engine's existing device/lease/grant/episode owner supplies authorization. Logout of the exact bound Phone authority first stops this module and attempts device revocation; other chat profiles do not affect it. Failed revocation persists and prevents local rearming until retried. The same APK shares a UID and process; this is not OS sandbox isolation.

Fixed capabilities are `android.observe` (bounded accessible node tree) and `android.action` (`click`, `long_click`, `set_text`, `scroll_forward`, `scroll_backward`). Actions require a fresh observation and all device/boot/control-session/app/window/node-map anchors. Password nodes, the host APK, Android permission controllers and system settings are excluded. There are no coordinate gestures, screenshots or continuous projection in this slice. Truncated trees/text carry `partial: true`; a missing tree is never represented as a screenshot or a successful observation.

`received` and `started` are persisted before driver invocation. Driver completion is `succeeded` with `businessVerification: unverified`; post-observation is evidence for Engine acceptance, never an automatic verified claim. A started action interrupted by disconnect/stop/restart becomes `unknown_outcome`. Duplicate command IDs return stored receipts after digest checks, with no re-execution. New commands require current authority/device/boot/local session/lease epoch/grant revision, local application scope, server grants, original TTL and deadline. Receipt storage is capped at 512 records and seven days; exhaustion fails closed. Old commands outside retention still fail the maximum 30-second action TTL.

The system service invalidates snapshots on accessibility events, stops on observed local interactions and screen-off/lock, and checks the live window and node again before applying. Android does not expose every ordinary raw touch to a normal accessibility service without changing touch exploration behavior. This module does not consume touchscreen events or claim universal human-touch interception; unseen input is additionally fenced by fresh snapshot/window/node validation and the always-visible local Stop action. OEM service reclaim can disconnect it; reopening locally is required after process death. No claim of unrestricted background availability is made.

## Build and verification

From the Phone directory, use its locked Expo 55 dependencies and `npx expo prebuild --platform android --no-install`. The local module is discovered through `expo-module.config.json`; Gradle merges the tracked module manifest/resources. Run `android/gradlew :v8-device-executor:testDebugUnitTest :app:assembleRelease` with the installed JDK/SDK. Test Android API 30 and newer, current Android behavior and an OEM device separately; an APK build alone does not validate accessibility permissions or action effects.

The synthetic target under `tests/android-executor-fixture` has no network/account/data permissions. Build with `android/gradlew -p tests/android-executor-fixture :app:assembleDebug`. It contains an increment button, a no-op button, editable synthetic text and a scene-change control. The no-op deliberately distinguishes driver acceptance from business completion.

Native instrumentation uses a separate test APK (`expo.modules.v8executor.test`) and never reads the existing Phone account. Start the Engine's isolated `tests/scripts/run_device_executor_live.py`, then run `scripts/prepare-executor-native-tests.ps1 -PublicTestCa <public-ca.pem>` and build `:v8-device-executor:assembleDebugAndroidTest`. The copied public certificate is ignored and trusted only by the test source set for `localhost`; release never trusts it. Forward `adb reverse tcp:9533 tcp:9533`, install the two test APKs, and manually grant the test service and notification from `ExecutorTestActivity`. Do not change system authorization with adb settings commands.

`ExecutorNativeTest` checks strict wire parsing, real SQLite crash recovery and authority-scoped receipt lookup. Real service testing uses the separate `ExecutorTestActivity` and an external `--live` harness, because Android instrumentation restarts the package and disrupts an already bound accessibility service. Start the test activity with the fixed `fixtureCommand=connect` intent after manually granting the test service. Its target is always the synthetic fixture, and its HTTPS origin is always the isolated localhost Engine. The fixture ticket is fetched and consumed inside native code. No credential or ticket belongs in shell arguments, reports or test fixtures. Production Phone upgrade requires a matching signing certificate; never uninstall a user's installed Phone to bypass a signature mismatch.

消息组件设计标准 / Draft 01
Message surface, not card gallery

让过程像工作记录，让产物像内容本身。

这套标准主动移除大圆角、彩色标题横框、玻璃拟态、发光阴影和层层套卡。消息正文保持开放；思考与工具进入可折叠工作日志；文件根据可预览程度采用“行、版、舞台”三种形态。

容器层级过多现状常见 assistant 24px 外壳 → 12px trace group → 8px thinking/tool，边框、背景与阴影重复。
02

03

04

01 / PRINCIPLES

先减少视觉主张，再增加信息清晰度。

组件不负责证明“这里有 AI”；它只负责把运行状态、结果与下一步讲清楚。视觉权重由内容价值决定，而不是由组件类型决定。

容器
采用开放排版、上下分隔线、必要的单层边界。
避免气泡套卡片、卡片套详情、每层都带圆角和阴影。
圆角
采用3 / 5 / 8 / 10px。媒体视口最多 10px。
避免18 / 22 / 24 / 30px 默认化，以及大面积 pill。
标题
采用与正文同一平面的小标题，13px，句式化表达。
避免独占整行的彩色横框、全大写标签和装饰性 icon。
状态
采用单个状态点 + 文本；颜色只落在点、关键数字和错误。
避免同一状态同时使用 glow、border、badge、icon 四层提示。
文件
采用缩略内容、扩展名、文件名、大小、可执行动作。
避免依靠一块 48px 彩色图标区分所有文件。

不是一种卡片，而是三种内容形态。

形态由内容能力决定。只有需要独立视口、交互边界或媒体裁切时才出现完整容器。

维度标准使用边界示例

边界1px hairline用于结构分区，不为每个状态重复着色。工作日志上下线、预览视口边界
